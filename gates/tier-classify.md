# Tier Classification Gate

Classify every change **before** starting work (Standard P8). The tier/lane sets how
much process applies. When in doubt between two tiers, pick the higher one or ask
`@host`. The declared tier is checked against the diff (`check-tier.sh`) — you cannot
self-downgrade a large change to skip gates.

## Decision

Answer in order; the first match wins.

1. Is production down or is this an urgent security exposure? → **Hotfix / Incident lane**.
2. Is this a mechanical change across many files (rename, framework bump codemod)
   that is one concern but a huge diff? → **Codemod / Sweep lane**.
3. Does the change touch persistent state, IO, security, auth, money, migrations,
   dependencies, or a public API/contract? → **Tier 1** (at least; + security gate).
4. Does it change observable behavior or add a user-visible capability? → **Tier 1**.
5. Is it part of a multi-issue milestone? → **Tier 2** (the child is still Tier 1).
6. Is it docs-only, comments, cosmetic, or read-only investigation? → **Tier 0**.

> A dependency bump is **not** Tier 0 even with "no behavior change" — route it
> through the security gate's supply-chain check.

## What each tier/lane requires

| | Tier 0 | Tier 1 | Tier 2 (EPIC) | Hotfix | Codemod |
|---|---|---|---|---|---|
| Plan gate | no | yes | per child | after-the-fact | yes (for the script) |
| Code-review (independent, P10) | inline | yes | per child | single approver | yes (script + sample) |
| Security gate | no | if auth/IO/state/deps | per child | if security fix | if deps change |
| Sign-off gate | no | yes | per child | backfilled | yes |
| Evidence packet | summary | full | full | **backfilled within window** | script + full-run |
| Tracker update | if applicable | yes | yes | yes + post-incident issue | yes |
| Real-use gate | no | if user-facing | **required to close** | smoke now, full later | full-run validation |

## Lane notes

- **Hotfix / Incident:** fix-forward fast, but the fast path is *logged*. Backfill the
  full evidence packet and open a post-incident review issue within a fixed window
  (e.g. 24h). The backfill is the enforced gate — urgency is not a permanent escape.
- **Codemod / Sweep:** the reviewable artifact is the **transform script** + a
  before/after sample + full-run validation, not the thousand-file diff. Split by
  compiles/tests-green safety boundary, not by file count. Declare "mechanical,
  generated by `<script>`" so the wide file set is expected.

## Record

State the tier/lane in the issue and PR. If you upgrade mid-flight (you discovered
state/IO/security), say so explicitly and adopt the higher process.
